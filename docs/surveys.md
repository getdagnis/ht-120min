# Tournament preference surveys

The first two fixed survey variants use the approved sequential manager overlay. `flag_hunters` is available for `around-the-world`; `exotic_hfi` is available to HFI tournaments in the `exotic-hfi` collection. The first team option differs; both variants retain the per-team comments and final manager-level 120-minute question. Pairing and scheduling do not read these answers yet.

Migration `145_tournament_preference_surveys.sql` established the private survey and preference storage. Migration `146_generalize_survey_table_names.sql` renames the tables to `surveys`, `survey_responses`, `team_preferences`, and `manager_preferences`, preserving their rows and IDs. `surveys.scope` distinguishes `tournament` from `site`; tournament surveys require a tournament ID and site surveys have none. The old table names remain service-only compatibility views for a safe application rollout. Migrations 145 and 146 have owner-added `-- applied!` markers; those markers do not independently verify live schema state.

`survey_responses` stores the latest submission per Hattrick manager and survey. Re-submitting replaces that row's answer and completion timestamp, and refreshes the independent current preferences; there is no version history or dismissal record. The GET handler normally hides a completed survey, while an already-open or repeated submission is accepted and updates the saved values. Closed surveys and responses remain available in Forge.

`team_preferences` is keyed by tournament, Hattrick team ID, and Hattrick manager ID; its current `priority` is the source for future team-level decisions. `manager_preferences` is keyed by tournament and Hattrick manager ID; its current `importance_120m` is the source for future manager-level decisions. They do not depend on a survey remaining active or a tournament-owned `teams` row retaining its UUID. A later settings UI can update them without changing the historical response. There is no settings UI or pairing consumer yet.

The `/api/app?route=manager-survey` handler uses the signed Hattrick app session, checks active non-reserve tournament teams owned by that manager, and validates one answer per team. One service-only database function inserts the historical response and upserts both operational settings in a single transaction; if any write fails, none are saved. The `/api/app?route=forge-surveys` handler requires the existing Forge admin session and `FORGE_ENABLED=true`; it creates fixed-template drafts, publishes/closes surveys, and reads responses. All four canonical tables have RLS enabled and no browser-role grants or policies. The browser never reads them directly.

The survey appears on the tournament page while it is active and the manager has not submitted. Closing it hides it for that page visit; a later visit shows it again. Forge displays live-roster participation totals while active and stored response totals when closed. Survey publication does not call CHPP or change fixtures.

Migration 146 must be applied before deploying code that reads the renamed tables. It preserves the active survey and old service-only table views. Site-wide survey targeting and participant response handling are not implemented yet; the scope column reserves the shared definition table for that future use. No application of migration 146 or browser verification is claimed here.
