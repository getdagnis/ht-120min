# Tournament preference surveys

The first two fixed survey variants use the approved sequential manager overlay. `flag_hunters` is available for `around-the-world`; `exotic_hfi` is available to HFI tournaments in the `exotic-hfi` collection. The first team option differs; both variants retain the per-team comments and final manager-level 120-minute question. Pairing and scheduling do not read these answers yet.

Migration `145_tournament_preference_surveys.sql` creates `tournament_preference_surveys` (one active survey per tournament) and `tournament_preference_responses` (one final submission per Hattrick manager and survey). A response stores the original manager-level choice and a JSON array of team choices, comments, tournament-team IDs, Hattrick team IDs, and display snapshots. The unique response key prevents a second submission; there is no answer-edit or dismissal record. Closed surveys and responses remain available in Forge.

The same migration creates two separate operational settings tables. `tournament_team_preferences` is keyed by tournament, Hattrick team ID, and Hattrick manager ID; its current `priority` is the source for future team-level decisions. `tournament_manager_preferences` is keyed by tournament and Hattrick manager ID; its current `importance_120m` is the source for future manager-level decisions. They do not depend on a survey remaining active or a tournament-owned `teams` row retaining its UUID. A later settings UI can update them without changing the historical response. There is no settings UI or pairing consumer yet.

The `/api/app?route=manager-survey` handler uses the signed Hattrick app session, checks active non-reserve tournament teams owned by that manager, and validates one answer per team. One service-only database function inserts the historical response and upserts both operational settings in a single transaction; if any write fails, none are saved. The `/api/app?route=forge-surveys` handler requires the existing Forge admin session and `FORGE_ENABLED=true`; it creates fixed-template drafts, publishes/closes surveys, and reads responses. All four tables have RLS enabled and no browser-role grants or policies. The browser never reads them directly.

The survey appears on the tournament page while it is active and the manager has not submitted. Closing it hides it for that page visit; a later visit shows it again. Forge displays live-roster participation totals while active and stored response totals when closed. Survey publication does not call CHPP or change fixtures.

Apply migration 145 before deploying code that reads these tables. Then enable Forge, create the draft using the tournament slug, inspect the variant, and publish when ready. No migration application, live submission, browser inspection, or deployment was performed by the agent.
