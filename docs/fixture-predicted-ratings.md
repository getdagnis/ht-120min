# Shared predicted fixture ratings

`fixture_predicted_rating_shares` is the source of truth for one team's shared prediction in one arranged fixture. It has one row per fixture and participating club, with a distinct row ID so a pending refresh can update only the same share. `share_source` distinguishes explicit manual shares from automatic ones; pre-existing rows remain manual. The row stores seven converted sector values, formation, tactic, tactic skill, the optional coach modifier, optional Set Pieces skill, the linked Hattrick MatchID, and the last successful fetch time. It never stores lineup, player IDs, raw XML, or credentials.

The public tournament projection and browser fixture refresh read `fixture_predicted_rating_share_status`, a narrow view that exposes only fixture ID, team ID, and MatchID for valid upcoming shares. Other visitors see a notice for each sharing club, or nothing when neither has shared. The base table is not publicly readable. A private, uncached `GET /api/app?route=fixture-ratings&tournamentId=...` returns both clubs' snapshots only to a signed-in manager whose stored credentials and live CHPP team list confirm ownership of an exact participating club. The values disappear at kickoff. On localhost only, the signed-in site admin identified by the configured `FORGE_SUPERADMIN_HT_ID` may see all upcoming shared snapshots when that variable is set to `8777402`; this exception does not apply in production. Share, Update, and Remove still require exact club ownership. Writes use the server's service role after session, fixture, and manager checks.

Share and Update fetch `matchorders` v3.1 with `actionType=view` for submitted positions, the taker, and the coach modifier, then `actionType=predictratings` for sector ratings and tactic skill. Only the exact -10/+10 coach-modifier endpoints are labeled and colored as Defensive 100%/Offensive 100%; neutral and intermediate settings remain unmarked. If there is a taker, `playerdetails` v3.2 adds the optional Set Pieces skill. The prediction request uses the saved match orders by omitting a lineup parameter. Sector values convert with `(raw + 3) / 4`. An unavailable optional player skill becomes `—`; a failed match-order request leaves any prior snapshot and timestamp intact.

## Automatic sharing

The Fixtures switch defaults to on for each team and manager in a tournament. `tournament_team_rating_preferences` stores only explicit preferences, without a season key, so opt-outs persist across seasons. GET/POST `/api/app?route=rating-sharing-preferences` uses signed-in sessions and live CHPP ownership verification. Tables and mutation RPCs are service-role-only; preferences do not affect who may read predictions.

Background fixture refresh creates an initial automatic share only for a current-season upcoming arranged fixture whose exact team's own `matches` response confirms `OrdersGiven=True`. Absent/false values do not trigger prediction reads, and another participant's fallback token cannot supply a positive orders check. Already-fetched match lists are reused. Fully reconciled fixtures normally skip the match-list read; automatic sharing reads the team's list only while it lacks an eligible share. A live token-holder club check still precedes prediction fetching. Initial creation is permitted by the stored default-on preference even when the refresh requester is not the owner; the response contains counts, never private values.

A team-row token is used for the orders check when available. A validated organizer addition without that token may use its recorded manager's saved profile credentials. This is an owner authorization lookup, not another participant's public-booking fallback. Missing or revoked owner authorization cannot create a share.

Once a valid share exists, background refresh neither reads orders for sharing nor fetches predictions again. An authenticated clicked Refresh fixtures updates existing manual and automatic shares in the actionable round after checking participation or tournament-management access. Updating an automatic share retains its automatic source. Explicit Share creates a manual share.

Switching off atomically deletes automatic shares for that team and cancels in-flight automatic claims; manual shares survive. Fixture Remove deletes its share and records suppression for the exact fixture/team/Hattrick MatchID, even if no row currently exists. Background refresh cannot recreate that match's removed share. Explicit Share clears suppression. Re-enabling the switch permits future automatic creation except for individually suppressed matches. Changed Hattrick MatchIDs have independent suppression.

`fixture_rating_automation` holds suppression, a two-minute claim, and a five-minute retry cooldown for pending/failed orders checks and prediction attempts. Concurrent refreshes claim the same side only once. CHPP requests run outside transactions, with a final atomic fixture/owner/preference/claim check before publishing. Preference writes and all Share/Update/Remove operations use the same tournament/team advisory lock. A removed row ID cannot be recreated by a clicked Update. A failed optional cache purge does not undo a successful write. Private client values reload when the public sharing-status key changes; switching off discards withdrawn local values immediately.
