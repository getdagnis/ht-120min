# UI locale catalog

The TypeScript dictionaries in `src/i18n/messages/` remain the source fallback and key registry. English is the default; empty Latvian values resolve to English. `src/i18n/catalog.ts` assigns each registered key to a Forge section. A key appears in Forge only when the running UI reads that dictionary key. News stories, tournament descriptions stored as data, manager names, and other user content are outside this catalog.

Forge `/forge/locales` offers component-scoped drafts and publications. `migrations/106_forge_locale_catalog.sql` prepares the settings, section, and immutable history tables. The migration is a file only until applied separately to Supabase. The consolidated `/api/app?route=forge-locales` handler checks a signed Forge session for administration, or a verified app session and an assigned locale editor ID for draft editing. Assigned editors can compare English but can write only assigned locales. Publishing and language settings require Forge admin authorization. Database tables have RLS and service-role-only grants; no browser Supabase writes are used.

Each publication copies one section's saved draft into published values and records an author and version in the same database transaction. Draft saves use a revision check so an older editor view cannot overwrite a newer draft. Restoring a published version copies its values into a new draft revision; it does not publish. The UI lists the most recent 20 publications per language and section.

`src/i18n/request.ts` loads published values at request time and falls back to the source dictionaries if the catalog is unavailable. The public layout passes those same values to both `next-intl` and the legacy locale context. Implemented languages appear normally in the switcher; beta languages include `[beta]`; draft languages are hidden and reject ordinary public navigation. Registered locale codes remain in `src/i18n/config.ts`. A Forge admin or assigned editor can preview a draft at `/{locale}?localePreview=1`; the proxy forwards the preview marker and the server verifies the session before reading draft values.

If the language-settings read fails, English remains available from its source dictionary. Other locale routes show the existing retryable unavailable state while visibility cannot be confirmed; a settings outage cannot turn a draft language into a public one or a temporary failure into a 404.

The current key registry covers all existing Home and shared-shell `next-intl` messages and an initial group of directly authored messages on Tournament View, Create Tournament, Tinder, and manager profiles. The remaining direct strings on those screens and their child components must be extracted before editors can control their full copy. Preserve ICU variables and approved rich-text tags when adding keys. Do not publish a section until its intended screen coverage has been inspected.

Local code, migration preparation, migration application, public rendering, and production deployment are separate verification steps. After applying migration 106, check Forge admin and assigned-editor access, draft save and conflict behavior, English comparison, per-section publication, history restore, beta/draft visibility, and the authenticated preview against real Supabase rows. A local build or mock does not prove the live database or production behavior.
